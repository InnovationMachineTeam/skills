# Worked Use Cases

These examples are concrete blueprints, not claims that a particular system has
already been deployed. Each blueprint shows the smallest reasonable operating
unit, roles, capability placement, documents, lifecycle, gates, and a ready-to-
use request.

| Domain | Examples | Default scale |
|---|---|---|
| [Agentic OS](agentic-os.md) | software factory, learning factory, research intelligence, startup operations | platform only after evidence |
| [Software delivery](software-delivery.md) | Web, Mobile, Desktop, full Discovery and Delivery | team; one agent for bounded reviews |
| [Learning and publishing](learning-and-publishing.md) | online/offline courses, trainings, workshops, textbooks, books | one agent or team by scope |
| [Research and innovation](research-and-innovation.md) | documentation, research, trendwatching, Design Thinking, Business TRIZ | one agent to team |
| [Business, growth, communication](business-growth-and-communication.md) | startup, Discovery Team, business tracking, marketing, public speaking | one agent to team |

Every example applies the same rules:

1. Prove why one agent is insufficient before creating a team.
2. Prove why a team runtime is insufficient before creating an Agentic OS.
3. Create skills with the agents: public only for multi-consumer reuse, private
   for one owner.
4. Register assets and bindings without confusing registration with activation.
5. Keep creation, evaluation, approval, activation, and publication separate.
6. Treat `docs/` as governed project memory with owners and provenance.
