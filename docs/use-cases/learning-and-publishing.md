# Learning, Training, Workshops, Textbooks, and Books

Learning products need outcome design, domain accuracy, practice, assessment,
facilitation, accessibility, production, and evaluation. Content volume alone
does not justify a team; independent expertise and artifact boundaries do.

## Common lifecycle

```text
audience evidence -> outcomes -> curriculum/structure -> source map -> prototype
                  -> content and practice -> assessment -> review -> pilot
                  -> revise -> publish/deliver -> measure -> maintain
```

## Common roles and capability placement

| Role | Main outputs | Likely private capabilities |
|---|---|---|
| Product/learning lead | audience, promise, scope, success metrics | learning-brief |
| Subject-matter expert | claims, examples, source accuracy | domain-specific authoring |
| Instructional designer | outcomes, sequence, practice, assessment alignment | backward-design |
| Assessment designer | item bank, rubric, validity evidence | assessment-authoring |
| Content editor | clarity, consistency, terminology | editorial-style |
| Media/visual producer | slides, diagrams, recordings, handouts | media-production |
| Facilitator/instructor designer | agenda, guide, timing, interventions | facilitation-design |
| Accessibility/localization reviewer | inclusive and localized artifacts | accessibility-review |
| Independent evaluator | frozen rubric, pilot evidence, verdict | learning-evaluation |

A reusable assessment contract or accessibility checklist may become public.
A course-specific tone, case library, or facilitator procedure normally remains
private to its owner agent.

## Online course

### Required materials

- audience and prerequisite profile;
- measurable course/module/lesson outcomes;
- curriculum map and lesson plans;
- source and citation map;
- scripts, readings, demonstrations, diagrams, and downloadable assets;
- guided practice, independent exercises, projects, answer keys, and rubrics;
- diagnostic, formative, and summative assessments;
- LMS structure, captions, transcripts, accessibility and localization package;
- learner onboarding, communication, support, and completion guidance;
- pilot protocol, analytics plan, outcome evaluation, maintenance calendar.

### Team or one agent?

One agent can produce a short internal asynchronous module when an SME and
human reviewer supply trusted sources. Use a team for credentialed, public,
multimedia, multilingual, or high-stakes learning.

### Example request

```text
Use agent-team-manager to design an online course production team for
"Practical Agent Evaluation". Include audience research, learning architecture,
SME authoring, exercises, assessments, rubrics, scripts, slides, transcripts,
captions, LMS packaging, pilot evaluation, and maintenance. Create the required
private/public skills and document ownership. Stop before publishing.
```

## Offline course

Add instructor scheduling, classroom constraints, print-ready learner workbook,
facilitator guide, room plan, equipment checklist, attendance, in-room
assessment, make-up policy, safety/accessibility, and train-the-trainer
materials.

```text
Create one instructor-enablement agent with private skills for facilitator-guide
maintenance and classroom readiness. It reads the approved curriculum and
pilot evidence, writes facilitator and logistics materials, and cannot change
learning outcomes without review.
```

One agent is appropriate here because the course already exists and the output
is one coherent enablement package.

## Online training

Training is usually shorter and behavior-focused. Required artifacts include a
performance gap, target behavior, scenario bank, demonstrations, coached
practice, job aids, action plan, pre/post measures, transfer-to-work follow-up,
technology rehearsal, breakout plan, and facilitator recovery options.

```text
Use agent-team-manager to create a virtual sales-training team. Separate domain
accuracy, instructional design, live facilitation, scenario/role-play design,
measurement, and independent pilot review. Produce participant, facilitator,
producer, and manager follow-up materials.
```

## Offline training

Add venue and safety plan, physical materials, room layout, equipment and backup
plan, observer rubrics, coach assignments, accessibility accommodations, print
control, attendance evidence, and after-action review.

For a single repeated workshop, one facilitator-designer agent with private
logistics and debrief skills may be enough. Use a team when content, operations,
measurement, and domain authority are separate.

## Online workshop

Required materials:

- precise participant outcome and selection criteria;
- pre-work and environment check;
- minute-by-minute agenda and producer run sheet;
- collaboration board/template;
- prompts, exercises, examples, breakout instructions, timeboxes;
- facilitator interventions and fallback paths;
- accessibility, recording/consent, and technical recovery plan;
- completed artifact definition, evaluation, follow-up, and reuse package.

```text
Create one workshop-designer agent for a 90-minute remote Design Thinking
session. Give it private agenda, Miro-board, and facilitator-script capabilities.
It must produce a tested run sheet and participant artifact template; a human
facilitator approves and runs the event.
```

## Offline workshop

Add room zoning, wall/board layout, supplies and print quantities, setup/teardown
checklists, safety/accessibility, photography/consent, table facilitation,
physical artifact capture, digitization, and post-event synthesis.

Use a small team for large or multi-table workshops: lead facilitator, table
facilitators, logistics producer, evidence synthesizer, and evaluator.

## Textbook

A textbook requires a stable syllabus or curriculum map, chapter outcomes,
concept dependency graph, definitions, worked examples, exercises by difficulty,
solutions/instructor materials, figures and permissions, citations, glossary,
index, accessibility, peer review, consistency checks, edition/version policy,
and errata workflow.

```text
Use agent-team-manager to design a textbook team for software architecture.
Separate lead author, chapter authors, technical reviewer, pedagogy/assessment
designer, editor, figure producer, citation/rights reviewer, and independent
quality evaluator. Define chapter templates and shared public skills only where
multiple author agents consume them.
```

## General-interest or professional book

The team may include concept/market researcher, author, developmental editor,
fact checker, sensitivity/domain reviewer, copy editor, visual producer,
citation/rights owner, and launch-material producer. One authoring agent plus a
human editor can be enough for a short, tightly scoped handbook.

Required artifacts include reader promise, competitive positioning, outline,
argument/evidence map, style guide, chapter briefs, manuscript, figures,
citations, permissions, review log, index/glossary where needed, production
files, errata and revision plan.

## Learning quality gates

- outcomes describe observable performance;
- content, practice, and assessment align to each outcome;
- claims and examples have provenance and domain review;
- accessibility and rights are designed in, not appended;
- pilot participants resemble the target audience;
- completion, satisfaction, and engagement are not mistaken for learning;
- transfer or application is measured when the promise requires it;
- publication has an owner, version, maintenance trigger, and withdrawal path.
