# Route: apply-practices

Audit or update declared skills against the current corpus.

1. Resolve exact target bundles and current hashes.
2. Run the generated modification prompt in read-only proposal mode first.
3. Produce a matrix of applicable, already satisfied, conflicting, inapplicable, and unverified practices per skill.
4. Route each accepted finding to `skill-doctor`, `skill-evaluator`, `skill-optimizer`, `skill-architect`, `skill-refactor`, or `skill-manager` through `skill-builder`.
5. Change one coherent hypothesis per target and preserve behavior, authority, host support, consumers, and unrelated edits.
6. Hand substantial or release-bound candidate revisions to `skill-evaluator` for independent routing, behavior, scripts, security, portability, catalog coexistence, holdout, and E2E evidence.
7. Stage new versions and verify rollback before lifecycle activation.

Never auto-apply every new practice to every skill. A practice update is evidence for review, not mutation authority.
