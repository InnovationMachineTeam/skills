# Route: architecture-design

Design the smallest architecture that satisfies the stated consumers.

Decide:

- canonical source root;
- flat versus one-level categories;
- aggregate plugin versus category marketplace entries;
- plugin and marketplace names;
- global skill-name collision policy;
- generated artifact boundaries;
- version authority;
- public/private distribution and authentication constraints;
- CI and release gates;
- migration and rollback shape.

Compare at most three viable options. Recommend one with explicit tradeoffs. Provide a target tree, manifest pattern, decision log, open decisions, and acceptance criteria. Stay in plan mode unless scaffolding is explicitly requested.
